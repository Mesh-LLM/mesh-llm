# Native KV and mixed scheduler evaluation

The optional generic runners use typed JSON inputs and the existing xtool owner. KV restart uses the backend-neutral dynamic host with its separately packaged native runtime, prepared through the normal release recipes. The matched mixed scheduler comparison instead requires its explicitly admitted standalone-static-skippy-server evaluation binaries and matching native-profile/model/config custody. Prepare those evaluation binaries through their existing named native evaluation prerequisites; do not substitute a release dynamic host. No command below downloads or builds these artifacts. Owning inert tests validate orchestration and evidence, not actual native-model or performance acceptance.

Run durable KV restart with `just kv-restart-replay /absolute/input.json /absolute/fresh-output`. The input schema is owned by `tools/xtask/src/automation/waiting_prefix/kv_command.rs::Input`. For the original default workload use:

```json
{"schema_version":1,"binary":"/absolute/mesh-llm","model":"/absolute/model.gguf","turns":4,"turn_target_tokens":4750,"system_tokens":500,"restore_repeats":3,"max_output_tokens":256,"request_timeout_secs":900,"ready_timeout_secs":900,"worker_timeout_secs":7200,"timeout_secs":30000,"serve_extra_args":[]}
```

The runner owns the default127.0.0.1:9337 endpoint, two lifecycle sessions and private state; that endpoint must be available. Fresh output preserves partial observations and terminal failure. A completed generic fixture does not attest real durable KV restoration.

Run the matched old/new scheduler matrix with `just mixed-prefill-decode-ab /absolute/input.json /absolute/fresh-output`. Input must supply the closed `mixed_matrix.rs::Input` contract: schema_version, old/new `adaptive_identity::Input`, shape `mixed_workload::Shape`, split, optional manifest, request_timeout_secs, worker_timeout_secs, suppressed_token_ids, timeout_secs, cell_timeout_secs and startup_timeout_secs. Use the actual owning CLI fixture's input builder as a schema example; substitute real artifact hashes/profile custody rather than claiming fixture pins certify a real build. Old/new model/config profiles must match. Alternating rounds, excluded warmup, per-role output and partial failure remain owned by the native command.

SystemOne continues through `scripts/skippy-system-one-smoke.sh`: default cases are native. Optional SYSTEMONE_SMOKE_DRIVER names an absolute regular executable with no symlink; Python drivers refuse. Existing native/runtime/artifact/qualified-backend gates remain active.

Competitive input acquisition and canary orchestration now have native owners. Their owning fixtures and original intent coverage do not establish real-family throughput, native model execution, external agents or protected hosted delivery.

The native adaptive and radix operators consume supplied, matched standalone-static Skippy evaluation artifacts; they do not prepare or download a model. Use `just skippy-adaptive-prefill-ab /absolute/input.json /absolute/fresh-output` and `just skippy-radix-cache-ab /absolute/input.json /absolute/fresh-output`. Their typed schemas are owned by `adaptive_matrix.rs::Input` and `radix_command.rs::Input`; existing actual inert CLI input builders demonstrate field shapes, not valid real artifact pins. Adaptive manifest preparation is `just with-lld cargo xtool automation waiting-prefix adaptive-prepare --input /absolute/input.json --output /absolute/prepared.json`. Excluded calibration/warmup, measured prefill telemetry, full matched roster/output parity and terminal cleanup remain required.

The waiting-prefix operator and its native preparation/report/acceptance contract are documented in `skippy/docs/SCHEDULER_FIXTURES.md`. Historical SVG evidence and chart behavior remain preserved. HF certification uses `cargo xtool automation hf-certify job-worker operator --input /absolute/operator.json --output-directory /absolute/fresh-output`: its closed input owns model-root, relative model-pattern, expected-parts and the worker request. Logical sorted part order survives canonical identity observation. Generic conversion and default Nemotron MTP composition use the native operators documented in [HF generic Jobs](HF_GENERIC_CONVERSION_JOBS.md) and [MTP composition](HF_MTP_COMPOSE_NATIVE.md). Native owning fixtures cover orchestration and bounded publication contracts; real native/model, prepared image and HF remote acceptance remain separate.
